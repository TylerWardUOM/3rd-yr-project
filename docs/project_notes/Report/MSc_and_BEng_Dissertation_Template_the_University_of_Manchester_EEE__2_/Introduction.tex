This section introduces the project motivation, problem definition, objectives, contributions, and scope limitations.

\subsection{Background and Motivation} \label{sec:introduction_background}

Robotic manipulators are increasingly used in domains such as industrial automation, teleoperation, and robot-assisted surgery, where safe interaction with physical environments is essential. Visual feedback provides important workspace information, but it does not directly communicate contact, constraint, or force-regulation cues.

Haptic interfaces address this limitation by enabling bidirectional physical interaction between a user and a virtual or remote environment. In robotic manipulation training, this can help users learn how to regulate force and respond to contact conditions, and prior work has shown that haptic feedback can improve task performance and reduce excessive applied force, particularly for less experienced users \cite{giriApplicationBasedReviewHaptics2021,bergholzBenefitsHapticFeedback2023}.

Despite these benefits, access to haptic systems remains limited in research and educational settings. Commercial interfaces provide mature force feedback, but are often expensive and tied to vendor-specific SDKs \cite{giriApplicationBasedReviewHaptics2021}. There is therefore practical motivation for low-cost, modular haptic platforms suitable for prototyping, experimentation, and robotics training research.

Achieving stable haptic interaction is technically challenging. Real-time haptic rendering commonly targets update rates on the order of 1~kHz with low latency \cite{ruspiniHapticDisplayComplex1997}, while delay introduces phase lag and reduces maximum achievable virtual stiffness \cite{adamsStableHapticInteraction1999}. A practical system therefore requires coordinated mechanical design, embedded control, communication architecture, simulation coupling, and force rendering.

\subsection{Problem Definition}

This dissertation addresses the design and evaluation of a low-cost real-time haptic interface system for robotic manipulation training. The challenge is to integrate sensing, host communication, simulation, haptic rendering, and actuator command output into a bounded bidirectional loop. Each stage introduces constraints: actuator capability limits rendered feedback, communication delay limits responsiveness and virtual stiffness, and software architecture determines extensibility.

Existing work demonstrates the value of haptic feedback and the feasibility of affordable haptic devices \cite{martinez3DPrintedHaptic2016,martinezOpenSourceModular2017,lavatelliDesignOpenSource2014}. However, less emphasis is placed on complete end-to-end architectures where hardware, embedded control, host-side simulation, rendering, and communication are developed and evaluated together. Communication architecture is therefore central, since buffering, scheduling, and transport delay directly affect stability and contact fidelity.

The problem addressed in this project is therefore defined as follows: \emph{to design, implement, and evaluate a low-cost haptic rendering system that is sufficiently modular for experimentation, sufficiently responsive for real-time interaction, and capable of bounded, controllable bidirectional haptic coupling with a simulated robotic environment}.

\subsection{Aim and Scope of This Dissertation}

The project demonstrates a complete end-to-end haptic architecture covering device construction, embedded firmware, host-side physics simulation, haptic rendering, visualisation, communication testing, timing analysis, and bounded-contact evaluation. The scope is intentionally limited: the dissertation does not attempt calibrated force output, commercial-level rendering fidelity, or a formal user study. Final hardware validation used force feedback on one joint only after actuator failure, so conclusions about full 2-DOF force rendering remain provisional. The principal contribution is therefore system-level design, integration, and evaluation under practical constraints.

\subsection{Objectives}

To achieve this aim, the project pursued five SMART objectives:

\begin{enumerate}[label=(\roman*)]
	\item Build a low-cost physical haptic interface with a total hardware cost below £200, capable of measuring joint position and accepting actuator torque commands during closed-loop operation.
	\item Evaluate whether host--device packet streaming can be sustained at a nominal 1\,kHz rate, while separately quantifying packet integrity, burst behaviour, and round-trip latency to determine the effective closed-loop timing limitation.
	\item Demonstrate that host-side computation is not the dominant timing bottleneck by measuring mean closed-loop host processing latency below 1\,ms during integrated operation.
	\item Verify safety behaviour by checking host-side force-command saturation, embedded torque limiting, torque slew-rate limiting, and watchdog torque removal during communication interruption.
	\item Evaluate physical interaction performance under motor-enabled contact and constrained-motion tests, reporting penetration bounds, rendered-force command consistency, and limitations affecting generalisation to full multi-axis force feedback.
\end{enumerate}

\subsection{Contributions of This Work}

Prior work on low-cost haptic platforms often focuses on hardware design or isolated demonstrations. This work instead co-develops and evaluates hardware, firmware, communication, simulation, and rendering as one system. Its principal contributions are:

\begin{itemize}
	\item \textbf{A complete end-to-end haptic rendering system.} Custom hardware, embedded firmware, a packet-based communication protocol, and a modular host-side framework with real-time physics and OpenGL visualisation are integrated into a single bidirectional pipeline and evaluated as a unified system. This type of co-design and cross-layer evaluation is less commonly emphasised in existing low-cost academic haptic prototypes.
	
	\item \textbf{Demonstration of bounded contact interaction under non-negligible communication delay.} Bounded, controllable contact behaviour was observed during the tested interactions despite a measured round-trip latency of approximately 15--16\,ms --- more than an order of magnitude above the nominal 1\,ms local haptic/device-loop period. This behaviour was achieved without a formal passivity guarantee through the combined use of virtual coupling, damping, snapshot-based communication, multi-threaded decoupling, and an embedded torque slew-rate limiter.
	
	\item \textbf{Quantitative identification of transport delay, not computation, as the dominant performance constraint.} Instrumented runtime logging isolates host-side processing latency from transport-layer delay (as quantified in Section~\ref{sec:results_host_timing}), demonstrating that the communication interface, not the host processor, is the bottleneck. This finding directly motivates communication-architecture improvements as the primary route to higher haptic stiffness in this class of system.
	
	\item \textbf{Characterisation of USB virtual-COM burst behaviour and a snapshot-based mitigation strategy.} Measured host-side packet inter-arrival times reveal strongly bimodal delivery: most packets arrive in near-simultaneous bursts separated by gaps of 14--16\,ms, consistent with buffering and scheduling in the ST-Link virtual-COM, Windows serial-driver, and host communication path. A snapshot-based channel design decouples the haptic rendering loop from this irregular delivery pattern, preventing stale-state accumulation without requiring changes to the communication stack.
\end{itemize}
